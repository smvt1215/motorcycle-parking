# 機車停車指南 · Lean UX Canvas v2

日期：2026-10-11。第 2 版，依既有計畫與本次 UI 回饋推導；下列產品成效尚未經使用者研究驗證。已確認的技術決策仍依 PLAN.md 執行，候選方案用於學習與比較。

| 欄位 | 假設草案 |
|---|---|
| 1. 商業問題 | 各縣市持續調整重機停放規則，資訊散落於公告、停車場與社群。新產品需要證明能幫騎士完成停車決策，才值得持續投入資料維護。近期回饋指出重複操作、搜尋範圍與條件不一致、存在回報入口不清楚；可能增加找位與維護成本。尚無營收、留存或既有使用量基線。 |
| 2. 商業成果 | 第一輪 8 位測試者中至少 6 位能在 2 分鐘內找到候選點並正確說明限制；至少 5 位願意在下次實際停車時再次使用；至少 6 位能在無提示的 30 秒內找到不存在回報入口。這些是實驗門檻，不是已確認 KPI；之後量測 7 日再次使用與找到點位後的導航比例。 |
| 3. 優先使用者 | 假設先以大台北黃／紅牌通勤者與跨縣市騎士驗證，再比較普通機車騎士。需確認誰最常遇到找位與規則不確定的問題，兩種車種皆保留於第一版。 |
| 4. 使用者成果 | 到陌生目的地能理解哪裡可停、費率與例外，減少繞路與停錯的焦慮；離開時能找到自己的車。觀察是否會先看限制與來源再選擇導航，而非只看綠色標記。 |
| 5. 候選方案 | 地圖＋車種資格與來源日期；可搜尋的縣市規則指南；人工整理的目的地停車建議。本次依授權採「目前範圍搜尋＋一致篩選＋統一修改建議」；另以獨立回報入口原型、官方更新＋人工維護做比較，後兩者是研究候選，不代表需重新實作獨立按鈕。停車紀錄仍保留，其價值待驗證。 |
| 6. 可測假設 | 若騎士透過目前範圍搜尋與一致篩選找到想看的格位，至少 6/8 人能在 2 分鐘內完成候選點選擇，並正確說明範圍及所選條件。若統一修改建議讓騎士能回報撤除點位，至少 6/8 人能於 30 秒內找到入口且說明回報後等待審核；若獨立入口原型更易被找到，與統一入口比較完成率及誤觸。 地圖假設：若重機騎士能用車種標記理解限制，至少 6/8 人能在 2 分鐘內找到適合的候選點。規則指南假設：若跨縣市騎士能快速閱讀來源與例外，至少 6/8 人能正確判斷免費／收費機車格的差別。人工建議假設：若提供目的地的核實建議，至少 5/8 人願意下次再次詢問，作為地圖價值的比較。 |
| 7. 最先學習 | 最大風險是假設騎士能區分「預設仍存在」與「合法可停／確定有位」，且能找到合併後的不存在回報。搜尋是否只限目前範圍與套用所選條件，也需觀察是否理解。若把標記誤認為合法保證，即使畫面易用也不能達成價值。 |
| 8. 最小實驗 | 先用現有 demo 做 30 分鐘可用性訪談，招募 4 位大型重機、4 位普通機車騎士；每人做陌生目的地範圍搜尋與格位篩選、辨識不適用格位、回報已撤除點位、記錄與找回車輛任務。詢問沒回報是否代表合法或有空位，觀察是否主動找修改建議，不先提示入口。不要以範例資料指引真實停車。記錄完成時間、誤判、來源查閱、下次使用意願。7 日內整理；若資格誤判超過 1 人、或找到回報入口不足 6/8 人，先修改資訊呈現再測，暫不擴大資料來源。 |

## 待驗證事項

- 優先族群、實際找位時間與資訊取得方式，需訪談佐證。
- 正確的官方資料仍不保證使用者能理解限制；需觀察而非只詢問喜好。
- 取消例行存在確認後，騎士是否願意回報異常、管理者能否及時審核，需另測貢獻意願與維護成本。
- 此版沒有加入分析 SDK；研究先採匿名人工記錄，不收集停車位置或身分。

每輪實驗後更新第 6–8 欄，記錄支持或推翻假設的證據。沒有測試結果前不把門檻當作產品成效。

## 本次證據與下一步

- 已知：使用者要求預設存在、統一修改建議，並檢討浮動搜尋與篩選；這是設計決策與需求證據。
- 尚未知：整併後的發現率、搜尋理解程度、實際維護成本；自動測試與截圖只驗證實作行為，不是使用者成效。
- 下一步：一週內用現有範例做上述 8 人任務測試，匿名記錄耗時、完成率、資格誤判與入口發現；結果寫回第 6–8 欄。沒有結果前不宣稱假設已驗證。
