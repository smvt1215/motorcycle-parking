# 雙平台設計與驗證

使用 frontend-design、gpt-taste 與 Lean UX Canvas 指導既有 Flutter 產品。原生導覽、可讀性與騎士操作需求優先；展示網站的 React／GSAP／AIDA 語法在此轉為 Flutter 原生動態与任務導向資訊順序。

- 色彩：海藍 `#176273`；可停深綠 `#186348`；條件琥珀 `#865500`；不可停暗紅 `#A13042`；待確認石灰 `#59646C`；紙白 `#FFFFFF`。Android 動態配色只作用於控制與內容，資格標記維持語意色。
- 字體：繁中採系統字體；拉丁文字與數字使用 Outfit。標題不截斷必要內容，放大字級時允許自然增高；觸控區至少 48。
- 結構：地圖滿版，控制放在上方、主要動作在下方。車位詳情可停在半高／全高，使用 root Navigator 顯示於最上層，覆蓋搜尋列、地圖控制與底部分頁；資格理由位於導航動作之前。規則頁使用短段落而非裝飾性卡片。
- 動態：採平台原生分頁與 sheet；資料狀態轉換可淡入，遵循減少動態效果。沒有自行播放的跑馬燈，資訊保持可閱讀。這是騎士任務需求對展示網站樣式的調整。
- 無障礙：狀態以形狀、文字與圖示共同識別；待確認與過時不等同合法性。操作不要求只靠長按，另有新增按鈕。

## 元件使用對照

使用者提供的地圖介面參考於 2026-10-11 優先套用：滿版地圖、上方圓角搜尋列、橫向篩選 pill、右下定位／記錄停車動作。底部改為「探索／個人中心／貢獻」；規則與收藏保留各自路由，入口集中在個人中心。「個人中心」與「貢獻」使用地圖背景上的可上拉面板，保留底部分頁與原地圖位置。貢獻面板提供新增停車點、修改資訊、补充重機資訊與檢舉入口。搜尋直接輸入並顯示下拉結果，僅比對目前地圖範圍內的停車點；空白與純空格不能送出。車種切換只保留篩選列的一個入口，移除搜尋列車種圖示與重複的圖層按鈕。瀏覽不需選擇縣市；拖曳或縮放停止 450 毫秒後，自動查詢可見範圍。跨市界時合併各縣市 TDX 資料，資格仍依各點所在縣市判斷。範圍過大或結果超過上限時提示放大；過時回應不能覆蓋新範圍。

範例提示移至左下角，避免遮住搜尋与停車標記。2026-10-11 改採 Google Maps：設定對應平台金鑰後使用官方 SDK，沿用現有控制與停車資料；未設定金鑰／離線測試時保留 OpenStreetMap 預覽，顯示實際來源署名。Google Maps 標誌與版權由 SDK 顯示，定位與記錄按鈕避開署名位置。Web 的浮動控制與面板需攔截 HTML 地圖事件；開啟面板或根 Navigator 的彈出層時，暫停底圖互動。Google Maps Platform 已啟用，實際載圖仍等待 API Key。

| 元件 | iOS 26+ | 舊版 iOS | Android / Web |
|---|---|---|---|
| 分頁 | CNTabBar | CupertinoTabBar | M3ENavigationBar |
| 導覽 | CupertinoNavigationBar + CNButton | CupertinoNavigationBar | M3EAppBar |
| 車種 | CNSegmentedControl | CupertinoSlidingSegmentedControl | M3EButtonGroup |
| 主要按鈕 | CNButton | CupertinoButton | M3EButton |
| 詳情 sheet | CNBottomSheet + DraggableScrollableSheet | 同左 | 官方 showModalBottomSheet + DraggableScrollableSheet |
| 表單 sheet | CNBottomSheet.showCupertino | 同左 | 官方 showModalBottomSheet |

根 Navigator 包含兩個官方 CompatibilityBridge，並註冊 CNTabBarRouteObserver。第三方相容橋接雖標示 deprecated，仍是此版本原生 sheet／tab 元件的必要依賴；套件升級後重驗。

Flutter golden 無法證明 native platform view 正確。iOS 截圖與 sheet 遮擋要以 macOS runner 真實模擬器檢查。Android 的动态色、返回手勢與系統列也需模擬器／實機验证。

詳情支援半高／全高：全高往下拖先停回半高，從半高再次往下拖才關閉；叉號或背景也能關閉。標題與關閉位於首列，收藏與分享位於次列，保留完整地點名稱。導航與修改建議放在資格理由之後，小螢幕或放大字級時上下排列。修改建議面板疊在詳情上方，必填內容送入既有審核佇列；範例模式明確標示只供測試。整體跟隨系統深淺色；Google Maps 使用本機深色樣式，OpenStreetMap 預覽只對圖磚轉色，兩者的資格標記都保留語意色。

## 搜尋與篩選檢討（2026-10-11）

原先「機車格」實際只篩收費格，且下拉搜尋略過地圖篩選；Enter 多筆結果時會直接開第一筆。現以明確格位選單取代六個分散按鈕，保留車種、格位類型、剩餘三種不同條件。搜尋與標記共用篩選，顯示筆數與已篩選提示；無結果時能直接清除條件。剩餘未知不代表有位。

搜尋列提示「搜尋此範圍停車點」，包含行政區比對；不暗示地址或 Google Places 搜尋已完成。右側改為搜尋按鈕，空白與純空格停用，純空格仍可清除。只有唯一結果會直接開啟，多筆維持選單供使用者決定。列高隨系統字級調整，結果可捲動並避開鍵盤，選取與關閉詳情後不自動展開。

## 修改建議與預設存在

未回報點位視同存在並繼續顯示。移除「還在／已不存在」獨立操作，將不存在併入「修改建議」底部的獨立項目，附「格位已撤除，或此處已無法停車」說明。回報必填現場狀況並送交審核；失敗保留輸入可重試。存在狀態與停放資格分開，資格理由、費率與來源保持可見。使用者研究假設與最小驗證任務見 [Lean UX Canvas](LEAN_UX_CANVAS.md)。
