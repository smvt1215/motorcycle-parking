# 雙平台設計與驗證

使用 frontend-design、gpt-taste 與 Lean UX Canvas 指導既有 Flutter 產品。原生導覽、可讀性與騎士操作需求優先；展示網站的 React／GSAP／AIDA 語法在此轉為 Flutter 原生動態与任務導向資訊順序。

- 色彩：海藍 `#176273`；可停深綠 `#186348`；條件琥珀 `#865500`；不可停暗紅 `#A13042`；待確認石灰 `#59646C`；紙白 `#FFFFFF`。Android 動態配色只作用於控制與內容，資格標記維持語意色。
- 字體：繁中採系統字體；拉丁文字與數字使用 Outfit。標題不截斷必要內容，放大字級時允許自然增高；觸控區至少 48。
- 結構：地圖滿版，控制放在上方、主要動作在下方。車位詳情可停在半高／全高，使用 root Navigator 顯示於最上層，覆蓋搜尋列、地圖控制與底部分頁；資格理由位於導航動作之前。規則頁使用短段落而非裝飾性卡片。
- 動態：採平台原生分頁與 sheet；資料狀態轉換可淡入，遵循減少動態效果。沒有自行播放的跑馬燈，資訊保持可閱讀。這是騎士任務需求對展示網站樣式的調整。
- 無障礙：狀態以形狀、文字與圖示共同識別；待確認與過時不等同合法性。操作不要求只靠長按，另有新增按鈕。

## 元件使用對照

使用者提供的地圖介面參考於 2026-10-11 優先套用：滿版地圖、上方圓角搜尋列、橫向篩選 pill、右下定位／記錄停車動作。底部改為「探索／個人中心／貢獻」；規則與收藏保留各自路由，入口集中在個人中心。「個人中心」與「貢獻」使用地圖背景上的可上拉面板，保留底部分頁與原地圖位置；面板可停在半高、九成與全高，往下滑到底部即關閉並回到探索，再次開啟時恢復九成高度。貢獻面板提供新增停車點、修改資訊、补充重機資訊與檢舉入口。搜尋直接輸入並顯示下拉結果，僅比對目前地圖範圍內的停車點；空白與純空格不能送出。車種切換只保留篩選列的一個入口，移除搜尋列車種圖示與重複的圖層按鈕。瀏覽不需選擇縣市；拖曳或縮放停止 450 毫秒後，自動查詢可見範圍。跨市界時合併各縣市的停車點（2026-10-17 起不含 TDX 即時資料），資格仍依各點所在縣市判斷。範圍過大或結果超過上限時提示放大；過時回應不能覆蓋新範圍。

範例提示移至左下角，避免遮住搜尋与停車標記；OpenStreetMap 署名與提示同一欄上下排列，不互相重疊，署名點擊區至少 44。iOS 的地圖延伸到懸浮分頁列下方，定位、記錄停車、提示、署名與 Google 標誌都依 Scaffold 回報的分頁列高度上移，不被分頁列遮住；面板清單底部同樣加上分頁列高度。2026-10-11 改採 Google Maps：設定對應平台金鑰後使用官方 SDK，沿用現有控制與停車資料；未設定金鑰／離線測試時保留 OpenStreetMap 預覽，顯示實際來源署名。Google Maps 標誌與版權由 SDK 顯示，定位與記錄按鈕避開署名位置。Web 的浮動控制與面板需攔截 HTML 地圖事件；開啟面板或根 Navigator 的彈出層時，暫停底圖互動。Google Maps Platform 已啟用；staging 測試版已帶入 Android／iOS Maps 金鑰，本機未設定金鑰時仍使用 OpenStreetMap 預覽。

詳情參考 Google Maps 地點面板（2026-10-23）：開啟時不加暗色遮罩，上方地圖保持清楚，點地圖即關閉；平板寬度上限 640。支援預覽高度（42%）／全高：全高往下拖先停回預覽，從預覽再次往下拖才關閉；叉號或背景也能關閉。名稱與關閉同列，收藏、分享移至副標操作列，保留完整地點名稱；副標依序為類型、縣市、行政區，已定位時加上直線距離。導航與修改建議固定在面板底部，捲動內容時仍可操作；小螢幕或放大字級時上下排列；有可用照片時，在現場補充分組以橫向照片列呈現，沒有照片時才在「現場補充」說明原因。修改建議面板疊在詳情上方，必填內容送入既有審核佇列；範例模式明確標示只供測試。表單依「基本資訊／可停車種／補充資訊（選填）」分段；格位類型以地面標線選擇格呈現（重用篩選的 `GroundMarking`，手機三欄、放大字級兩欄，同列等高），騎士對照地面標線挑選。車種資格用分段選項（未確認／可停／不可停）取代下拉選單，並以綠白牌、紅黃牌色塊標示車種；資格依標線帶入：機車格帶入普通機車可停，重機專用格帶入普通機車不可停、大型重機可停，汽車格帶入普通機車不可停，其餘皆為未確認。使用者手動改過車種後，換格位不再覆蓋；提示文字說明「現場有告示牌或地面標字時，才選『可停』」。新增停車點說明位置來源（地圖中心或長按位置）並把座標降為次要資訊；取消放在標題列，長表單不必捲到底。修改建議清單顯示每一項的目前值；格位類型重用地面標線選擇格，停放資格用帶車牌色塊的分段選項，說明欄選填；驗證錯誤顯示在對應選項下方；送出前以「你要改的內容」卡片列出每項變更（停放資格只列有變更的車種）。不存在回報的項目稱為「這裡已經不能停車」；收費改用共用的 `FeeEditor`（`lib/ui/fee_editor.dart`，App 與管理站共用）：普通機車、大型重機各選收費方式（未確認／免費／依現場公告／計時／計次／每日，大型重機另有比照機車、比照汽車），只在需要時展開金額、計費時間、當日上限或一次可停時間；欄位寬度足夠（≥ 520）時並排，手機上下排列；下方即時顯示將寫入 `fee_note` 的文字；P4（2026-10-25）：選「路外停車場」時，新增停車點與格位建議都追問場站型式（未確認／立體／地下／平面）與停放分類；新增停車點另有「入口在哪裡」與最多 10 個分區（外框卡片，每區名稱、停放分類、怎麼停）。所有格位的「停車指引」與「其他備註」分開填寫，路邊格的指引提示改為描述格位位置。可停車種先依標線帶入，標線無法判斷的車種再依該縣市的停車規則帶入，提示文字註明來源；手動修改後不再覆蓋。修改建議的「位置或其他備註」拆成「入口與停車指引」（只送有變更的欄位）與「其他備註」，「停車點位置」建議以共用位置選擇元件拖曳標記送出新座標（2026-10-26）；新增停車點的位置也在表單內用同一元件調整，長按或地圖中心只當起始位置。「這裡已經不能停車」先選原因（格線已撤除、改為其他用途、施工中、暫時封閉、其他）：只有前兩種永久原因建議隱藏，施工與封閉可填預計恢復時間，選「其他」時說明必填；未登入時以提示卡片引導登入。整體跟隨系統深淺色；Google Maps 使用本機深色樣式，OpenStreetMap 預覽只對圖磚轉色，兩者的資格標記都保留語意色。

定位（2026-10-23）：開啟 App 時自動定位。定位服務關閉或未授權時，以對話框說明原因並提供「開啟定位設定」／「前往設定」按鈕（Web 無設定頁，只顯示說明）；定位鈕與記錄停車遇到同樣情況也跳出同一個對話框，不只顯示一行訊息。啟動時若定位已有結果，先提醒定位再顯示第一次的圖例；定位尚未有結果時先顯示圖例，結果出來後再提醒。從設定返回 App 時只檢查權限、不再次跳出系統詢問，已允許就直接定位並移動地圖。

UI 修正（2026-10-24）：Google 登入在行動裝置使用系統瀏覽器，callback 由 Supabase 的 app_links 接收；Android 與 iOS（含 Debug）關閉 Flutter 預設深連結路由，避免登入回跳被當作不存在的頁面。數字停車點群聚標記統一為 56dp 藍色圓圈與 20dp 粗體數字，Google Maps 與 OpenStreetMap 預覽一致；定位藍點維持原尺寸。Google Maps 原生群聚未提供尺寸設定，改以像素距離分組並繪製共用樣式的 bitmap 標記，點擊放大兩級，20 級時展開為單點。底部面板直接疊在地圖上；開關面板不再調整 Google Maps padding，iOS 表單也不縮放底下頁面。選取停車點時以一次相機移動將點位置中於面板上方；面板直接疊在底圖，關閉時相機不回復、不向下回彈。搜尋選取與定位按鈕仍會移動地圖。建議送出成功後，按完成、叉號、返回或下滑關閉表單時，同時關閉「提出修改建議」父面板並回到詳情或原分頁；取消或送出失敗則保留父面板。

登入與群聚調整（2026-10-25）：新增停車點與修改建議在原表單直接選 Google／Apple 登入；貢獻頁與詳情的精簡入口只開登入選單，成功後收起選單並回到原頁，不開啟帳號設定。既有帳號設定頁登入後仍保留該頁。App 監聽登入狀態轉換，在底部顯示 3 秒「登入成功」提示，置於所有頁面與表單之上且不攔截操作；既有登入狀態的啟動、重複登入事件與一般資料更新不重複提示。表單與詳情監聽 AppStore，即時更新登入提示、可用操作與送出按鈕，保留草稿。兩種地圖共用同一套以像素距離分組的規則：同一鄰近群組至少 5 點才顯示藍色數字圈，1～4 點保留原座標的個別標記；56dp 圓圈、點選放大兩級、20 級拆回單點與選取點獨立顯示維持原行為。

## 搜尋與篩選檢討（2026-10-11）

原先「機車格」實際只篩收費格，且下拉搜尋略過地圖篩選；Enter 多筆結果時會直接開第一筆。現以明確格位選單取代六個分散按鈕，保留車種、格位類型、剩餘三種不同條件。搜尋與標記共用篩選，顯示筆數與已篩選提示；無結果時能直接清除條件。剩餘未知不代表有位。

搜尋列提示「搜尋此範圍停車點」，包含行政區比對；不暗示地址或 Google Places 搜尋已完成。右側改為搜尋按鈕，空白與純空格停用，純空格仍可清除。只有唯一結果會直接開啟，多筆維持選單供使用者決定。列高隨系統字級調整，結果可捲動並避開鍵盤，選取與關閉詳情後不自動展開。

## 修改建議與預設存在

未回報點位視同存在並繼續顯示。移除「還在／已不存在」獨立操作，將不存在併入「修改建議」底部的獨立項目，附「格位已撤除，或此處已無法停車」說明。回報必填現場狀況並送交審核；失敗保留輸入可重試。存在狀態與停放資格分開，資格理由、費率與來源保持可見。使用者研究假設與最小驗證任務見 [Lean UX Canvas](LEAN_UX_CANVAS.md)。

## 點位詳情十二欄分組版（2026-10-12）

使用者已核准以四組顯示十二項資料，沿用半高／全高詳情面板。名稱位於全寬標題列，收藏與分享位於次列；正文以分隔線與資訊列建立層級，窄螢幕或放大字級改為標籤在上、內容在下。資格理由保持在導航與修改建議之前，使用既有資格判斷，不將新的車種分類視為法律判定。

| 區塊 | 使用者指定欄位 |
|---|---|
| 停車資訊 | 1 名稱（標題）、2 類型、3 費率、4 停放車種 |
| 位置與指引 | 5 入口與停車指引、6 地址／路段／GPS、7 特殊規則 |
| 現場補充 | 8 照片、9 備註 |
| 資料與查核 | 10 資料來源及狀態、11 更新時間、12 即時車位狀態 |

場地類型與停放車種分開：場地型式為立體、地下、路外平面或路邊；沒有型式資料的路外場顯示「路外停車場（型式未提供）」。停放分類採普機專用、普大共用、大汽共用、機車不可停、大重專用；有分區資料時逐區顯示分類、費率與指引。兩種車種都可進入停車場，不足以推定共用同一格位；證據不足仍列各車種資訊與「格位配置未確認」。

缺欄位顯示「未提供」，未知資格顯示「未確認」，沒有照片顯示「尚無照片」。照片支援點選放大與縮放，載入失敗顯示可讀提示；只有真實資料提供的照片連結才載入。路邊格隱藏停車場入口與即時車位欄，停車指引仍保留。停車場沒有車位數時顯示「暫無即時資訊」，零格仍明確顯示零；車位資料時間獨立於點位更新時間，未提供時明示。

舊 TDX 路外停車場回應只有通過即時時間驗證才提供剩餘格數，因此有格數且缺少獨立車位時間時，可使用其 `updated_at` 作相容顯示；其他來源不套用此回退，新車位時間欄位優先。

資料模型新增選填的 `facility_type`、`parking_access`、`address`、`road_segment`、`entrance_note`、`parking_guide`、`special_rules`、`photo_urls`、`parking_zones`、`availability_updated_at`，舊 JSON 與收藏可繼續讀取，新欄位亦隨收藏保存。空白選填欄位不加入既有寫入內容。本輪處理詳情顯示與資料相容性；來源尚未提供的欄位使用上述缺漏顯示。2026-10-17 起 `community_spots` 與 `official_heavy_spots` 都有對應的後端欄位（migration `202610170002_spot_detail_fields.sql`，照片限 https、最多 10 張），`viewport_spots` 與 `official_viewport_spots` 一併回傳；回報表單已擴充場站型式、停放分類、入口、指引與分區（#73、#75），照片上傳仍依後續計畫安排，即時車位暫停。

## 詳情資料與車種圖示（2026-10-25）

採停車判斷優先設計：預覽先呈現名稱、資格、收費與格位／剩餘車位。正文依停車資訊、位置與指引、現場補充、資料與查核分組，空白入口、指引、規則與備註省略，必要的資料狀態集中提示，地址優先、座標以輔助文字呈現。修改建議直接覆蓋原面板，不強制展開父面板。

普通機車、大型重機與汽車使用不同圖示；專用呈現單一車種，共用以連接符號串連兩車種，並搭配文字。停車場兩種機車皆可進場不推定共用格；有分區時，車種、費率與指引同組顯示，未確認分區不繼承其他區資格。資料描述與目前車種的法規資格判斷仍各自呈現。設計與驗證見 [詳情面板整理](designs/2026-10-25-spot-detail-panel.md)。

共用格位與費率分開描述：parking_zones 可選填 scooter_fee_note、heavy_fee_note、car_fee_note，分別呈現原始價格、單位與條件；某一適用車種未填費率時顯示「費率未提供」，不沿用另一車種或一般 fee_note。單一分區的摘要跟隨目前車種，多分區保留各分區個別資料。舊資料維持一般費率文字，現有 JSONB 儲存不需 migration。

資格顯示分層（2026-10-25，核實計畫 §3.4）：`EligibilityStatus` 的判斷不變，詳情橫幅另依 `lib/domain/eligibility_display.dart` 的 `eligibilityDisplay()` 說明判斷依據。已判定的結果標示來源與日期（「依政府公開資料，更新於…」「管理員確認，2026-10-25」，盾牌圖示；管理員確認可停時說明只寫「請確認現場公告」，不重複「可停」，#132）；社群路外場站只有車友回報時顯示「車友回報可停」或「車友回報不可停」，附「回報於」（匯入點為「匯入於」，取 `created_at`：車友只在新增時寫入車種欄位，`updated_at` 會被投票與狀態變更刷新，`last_confirmed_at` 只代表存在確認）與「請以入口公告為準」；管理員確認超過 180 天回落時顯示「曾確認可停／不可停」，依據行「管理員確認，日期，已超過 180 天」配時鐘圖示，標記圖示維持問號；車友回報與確認過期的說明為「可停放車種未經確認，請以入口公告為準。」（停車點已確認存在時前面加「此處確實有停車點，」）；沒有車種資料維持「開放資訊待確認」。路邊格位依縣市規則顯示，不分層。橫幅沿用地圖標記的語意色與形狀，所以車友回報仍是灰色待確認色，並以「車友」圖示取代問號，不使用可停的 P 圖示；車種以雙色小車牌標示（25×17，後牌在左上、前牌往右下錯開 7、5，普通機車綠疊白、大型重機紅疊黃，邊框淺色 #16313A、深色用前景色，#131），資格結論是唯一的粗體標題。「資料與查核」新增「已確認欄位」，逐車種列出「普通機車可停：管理員確認，日期」，過期另行註明，沒有確認時顯示「尚未確認」。收藏與我的貢獻列表使用相同的短標籤，地圖標記維持四態。「回報不一致」這一層目前沒有欄位級爭議資料可以判斷，等 `spot_field_verifications` 上線後再加入。

結構化分區費率（2026-10-25）：parking_zones 每區可選填 `fee`，格式與點位 `fee` 相同。費率優先順序為「分區自己的結構化 fee → 點位 fee → 舊文字」，缺少的車種顯示「費率未確認」。所有分區都沒有自己的 `fee` 而點位有 `fee` 時，正文先列「全場費率」，分區不再顯示舊的機車費率文字；結構化費率沒有汽車金額，分區的 `car_fee_note` 仍照常顯示。只要有任一分區有自己的 `fee`，就逐區顯示：有 `fee` 的分區顯示結構化費率，沒有 `fee` 的分區照原本的舊文字顯示，不沿用全場費率（使用者決定）。

費率不再於「停車資訊」重複列一個欄位：預覽保留摘要，各車種／分區的價格放在對應圖示下，額外計費條件才另列收費說明。沒有分區費率的舊資料在摘要完整顯示原始費率文字。系統分區標題及預設名稱統一使用「分區」，既有資料自訂的分區名稱保留原文。

照片回饋修正（2026-10-25）：副標將縣市與行政區合成完整地區，類型與距離仍分開。即時車位僅在頂部摘要顯示一次，包含已知總格數與資料時間；下方移除重複車位狀態列與查核狀態列（不論是否確認）。已確認存在的社群場站仍保留未查核的車種判斷，並明示「目前車種是否開放仍待查核」。來源依公開回報者欄位顯示「由車友 XXX 回報」「由管理員新增」或「由管理員自其他社群統整後匯入」，不公開帳號識別；官方保留提供機關。社群移除外部來源與內部授權文字，官方的授權入口固定至政府資料開放授權首頁。

導航與返回停車位置共用導航行為：iOS 優先直接開啟 Google Maps App，無法開啟時改開 Apple Maps；Android 與 Web 使用 Google Maps 導航網址。直接嘗試啟動並處理回退，不以安裝查詢結果停用導航。

## App 圖示與啟動畫面（2026-10-25）

圖示直接使用使用者提供的插畫（藍底、白色速克達、紅色定位針＋藍色 P、地面停車格標線）。`assets/branding/app_icon_source.png` 是去掉白邊、四角以相鄰藍色補滿的滿版 1024 px 版本（無透明通道），由 `tool/render_brand_icons.py --from-original` 從原圖產生；同一支腳本再轉出 adaptive 圖層、啟動畫面標誌、Web 圖示與 staging 圖示，之後由 flutter_launcher_icons（Android／iOS）與 flutter_native_splash（原生啟動畫面）產生平台檔案。兩個產生器會改寫 `AndroidManifest.xml` 的 `${appIcon}`、`project.pbxproj` 的 staging 圖示設定與 `Info.plist` 格式，重新產生後要還原這三個檔案。

插畫是單張點陣圖，無法拆成前景與背景：Android adaptive icon 把整張圖放在背景層，縮到定位針與機車落在 66dp 安全區內，外圍延伸原圖邊緣的顏色，前景留空。主題化（monochrome）圖示需要另外畫單色剪影，因此不提供，Android 13+ 開啟主題化圖示時仍顯示彩色圖示。Staging 圖示是同一張圖加上黃底「TEST」色帶，Android 的色帶位於安全區內，也不提供 monochrome，主題化時仍看得到 TEST。

原生啟動畫面不放文字或動畫：淺色為停車標誌藍 `#1F5FA8` 底，深色為柏油 `#1C2126` 底，中央是 150dp 的圓角圖示（288dp 畫布），Android 12+ 的 192dp 圓形遮罩內完整可見。Flutter 載入畫面延續同一個底色與同尺寸、同位置的圖示，圖示下方 20dp 起顯示 App 名稱「機車停車指南」與副標「普通機車・大型重機」（2026-10-26 加回），底部顯示載入狀態、提醒與版本；螢幕太矮時圖示先縮小（最小 40dp）讓名稱放得下，連 40dp 圖示都放不下名稱時只保留圖示、名稱不顯示，任何情況都不壓到文字。

## 即時車位 P0（2026-10-26）

可不可以停與有沒有位分開呈現，見 [設計稿](designs/2026-10-26-realtime-availability-ui.md)。動態剩餘數以 `lib/models/availability.dart` 的 `AvailabilitySnapshot` 與靜態 `ParkingSpot` 分開；狀態依來源時間分新鮮、延遲、過期，另有無資料（`null`、`-1`、`-9`、容量 0）、暫停與異常（剩餘大於容量、其他負值、未來時間、長期為 0）。路外停車場的標記正上方掛中性墨色膠囊（密集時每點只留一個主要膠囊，選取時顯示完整一組並隱藏碰到它的鄰近膠囊）：新鮮「剩 N」（墨色）、「已滿」（淺灰）、延遲為描邊加線條時鐘、「暫停」（深紫加暫停圖示），未知或目前車種不可停時不掛膠囊（不可停的詳情寫「不顯示空位」）；圖例在範例模式另列這幾種膠囊；大型重機模式且場站確認 `heavyCar` 時另掛汽車格膠囊（汽車圖示＋「剩 N」）。詳情摘要右欄顯示大數字「剩餘／共 N 格」、更新時間與來源，或「無即時資料」「空位未知」「資料過期」「暫停營運」；重機沒有數字時，機車與汽車格數字只當次要列。「目前有位」只留新鮮、有位、可停或有條件可停的點，其餘改為灰色小圓點並在空結果卡列出原因，未知永遠不算已滿。P0 只有範例模式的 fake 資料源；連上後端時不顯示膠囊與篩選，真資料、Google Maps 的數字圖層與排程在 P2。路邊格維持原本的地面格位顯示。

停放車種區（#130）不再顯示「大型重機與汽車共用」這類說明行，只留車種格（圖示、車種名、共用／專用）與 ⇄ 圖示；完整說明保留在 Semantics。格位未確認時仍顯示「格位配置未確認」。
